# Decisions · today

Appended, never edited: a decision that changes is superseded by a new entry, which names the one it
replaces. An entry is written for whatever would otherwise be argued again: each gate's outcome, each
pick, each exception, each deferral. A decision that changes the product, and not only this design, is
also logged where the project's profile says, in `decisions-log`.

## D-01 · A working surface, sized a surface

2026-11-10 · frame · all

**Decision.** The design is a working surface, sized a surface, and every stage runs full.

**Why.** It is a new screen she works on all day.

**Rejected.** An adjustment: there is no screen to adjust.

**Cost, accepted.** Nine stages for one screen.

**Consequence.** None on the build yet.

## D-02 · Practitioners do not reach this screen

2026-11-11 · context · all

**Decision.** The screen is for the front desk alone. Practitioners ask the desk.

**Why.** The founder corrected it: the desk places every patient.

**Rejected.** A screen for both roles: two jobs, and it would be two surfaces.

**Cost, accepted.** A practitioner still phones the desk to ask.

**Consequence.** No practitioner sign-in reaches this screen.

## D-03 · The job is a walk-in in a room that is free now

2026-11-11 · intent · all

**Decision.** One job: put a walk-in in a room that is free right now, without leaving the desk. Three criteria, two tasks.

**Why.** It is the moment that costs her a phone call today.

**Rejected.** Planning the day ahead: the context rules it out.

**Cost, accepted.** A booked patient gains nothing from this screen.

**Consequence.** A booking can be undone for two minutes, on the screen she is on.
